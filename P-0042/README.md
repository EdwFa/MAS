# P-0042: сквозной каркас практикума

Агент готовит справку к онкологическому консилиуму по случаю P-0042. Каркас собирает в одном пакете код из лекций 3–9, 13 и 18: каждый практикум курса дописывает или заменяет одну деталь, а остальное продолжает работать.

Все данные вымышленные: пациенты P-0042 и P-0051, карта в формате FHIR, тексты документов, хронология по дням и учебный текст «рекомендаций» с УУР/УДД. Описание случая и заложенных ловушек — в [`data/README.md`](data/README.md). Это не клинические рекомендации, и расчёты каркаса не предназначены для решений о лечении.

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pytest                      # 33 теста, без сети и без модели
```

Агент на локальной модели (любой сервер с OpenAI-совместимым API: Ollama, vLLM, llama.cpp):

```bash
export P0042_BASE_URL=http://localhost:11434/v1   # по умолчанию
export P0042_MODEL=qwen3:8b                        # любая локальная модель
python run.py "Посчитай СКФ по последнему креатинину и найди, что рекомендации говорят о сниженной функции почек"
```

`LocalLLM` принимает только адрес на `localhost`: данные пациента не покидают контур (152-ФЗ). Трасса каждого шага пишется в `trace.jsonl`.

MCP-сервер отдельно — для подключения к любому клиенту MCP:

```bash
python -m p0042.server      # stdio
```

## Протокол агента

Модель отвечает одним JSON-объектом:

```json
{"tool": "latest_lab", "args": {"case_id": "P-0042", "test": "креатинин"}}
{"final": {"answer": "СКФ 41 (G3b) по креатинину от 13.11", "sources": ["Observation/crea-233"]}}
```

Harness проверяет, что каждый источник в ответе агент действительно видел в наблюдениях. Придуманная ссылка даёт статус `needs_review`, а не `complete`.

Возможные статусы: `complete`, `needs_review`, `waiting_doctor` (пауза — не ошибка), `step_limit`.

## Задания по лекциям

Каждое задание — отдельная ветка и pull request с тестами.

- **Лекция 4.** Добавить инструмент `latest_encounter` и политику «спросить» для любого инструмента с побочным эффектом. Тест: неизвестный инструмент и лишнее поле в аргументах дают понятную ошибку.
- **Лекция 5.** Записывать в память состояние сборки пакета по дням со ссылками на записи. Тест: «среда» продолжает с «понедельника», а поиск по P-0042 ничего не находит из P-0051.
- **Лекция 6.** Перевести `chart_write` на сервер MCP с `InputRequiredResult` (MCP 2026-07-28) и подключить сервер к harness как клиент. Тест: изменённое описание `lab_reference` отсекается `admit`.
- **Лекция 8.** Заменить `hashed_embed` и `overlap_rerank` на локальные модели. Добавить 30 вопросов с эталонными пунктами и посчитать метрики каждого модуля.
- **Лекция 9.** Подключить `route_question` и `answer_loop` к harness. Сравнить прямую цепь и поток по видам вопросов.
- **Лекция 18.** Собрать набор для `gate` (вопросы и атаки), показать один релиз, который проверку не проходит; тихий режим на 10 размеченных пакетах; `RUNBOOK.md`: отказы, откат, роли, ручной режим.
- **Лекции 13 и 17.** Добавить общий бюджет времени и проверку «спор дат → открытый вопрос в пакете». Тест: агент не выбирает одну из двух дат консилиума молча.

## Ограничения каркаса

- Заглушки эмбеддера и переранжировщика нужны, чтобы тесты шли без моделей; качество поиска с ними учебное.
- `Store` держит данные в памяти процесса. В эксплуатации — база данных.
- Разметка рекомендаций простая: заголовок раздела — строка вида «3.2 Название», пункт — «3.2.1 Текст».
