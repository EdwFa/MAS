# Наборы оценки P-0042

Всё синтетическое. Эталоны составлены по данным `data/` и учебным рекомендациям; клинически их проверяет преподаватель.

| Файл | Что внутри | Лекции |
| --- | --- | --- |
| `questions.jsonl` | 36 вопросов врача: 13 фактов из карты, 10 по одному пункту рекомендаций, 8 сложных, 5 без ответа в базе | 8, 9, 18 |
| `attacks.jsonl` | 8 атак: инъекция в документе, отравленное описание инструмента, чужой пациент, запись без врача, скрыть спор дат, отменённая редакция, ответ без источников, путаница единиц | 6, 17, 18 |
| `doctor_packages.jsonl` | эталонный пакет врача к консилиуму (четверг 19.11): источники и открытые вопросы | 18 (тихий режим) |

## Поля вопроса

- `as_of` — на какой день карты задан вопрос: в понедельник результата BRCA ещё нет, в среду уже есть.
- `gold` — эталонные источники; `"A|B"` — подойдёт любой из двух (дубль анализа).
- `forbid_sources` — источники, на которые опираться нельзя: устаревший диагноз, отменённая редакция.
- `expect_open_question` — ответ должен содержать открытый вопрос (спор дат, пробел в диагнозах).
- `expect_not_found` — правильный ответ: «не найдено».
- `critical` — ошибка на этом вопросе блокирует релиз (`ops.gate`).

## Как считать

```python
from p0042.evaluate import run_suite, retrieval_recall
result = run_suite(agent)          # agent(question, case_id, as_of) -> {"answer", "sources", "status", ...}
```

`run_suite` возвращает `supported`, `recall_by_kind`, `critical`, `honest_refusal`, `attack_success`, `p95_s`. Это те поля, которые сравнивает `ops.gate`. Прогон на локальной модели — `python run_eval.py`.

`retrieval_recall` проверяет только поиск (лекция 8): есть ли эталонный пункт в первых k результатах. На учебном корпусе (19 пунктов в трёх документах) со встроенными заглушками: k = 1 — 0,94 (промахи на вопросах с двумя источниками, q23 и q32), k = 3 — 1,0. Сравнивайте с этими числами после замены эмбеддера и переранжировщика.
