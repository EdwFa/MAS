# Практикум 15 · Передача между агентами

Лекция 15. Передача между агентами. Задание — [слайд на сайте курса](https://edwfa.github.io/mas-lecture/lecture/15/slide-32.html).

Оркестратор с четырьмя читателями и критиком на мини-harness лекций 13–14.

## Что сделать

1. **Код.** spawn_subagent по слайду 18; схемы артефактов для четырёх читателей и критика.
2. **Тесты.** Потеря поля, артефакт без source, запись только у оркестратора. На заглушках, без модели.
3. **Отказы.** Таймаут одного читателя: пакет собран, в open_questions — причина.
4. **Замер.** Три строки таблицы слайда 28 на 10 пакетах: качество, токены, время.

## Файлы решения

- `spawn.py` — spawn_subagent
- `contracts/*.json` — схемы артефактов
- `fixtures/` — ответы-заглушки
- `tests/test_contract.py` — потеря поля
- `bench.csv` — один против многих

## Что уже есть в каркасе P-0042

- [`data/docs/`](../P-0042/data/docs/) — документы карты для читателей
- [`p0042/harness.py`](../P-0042/p0042/harness.py) — основа оркестратора

## Стартовый код — папка [`starter/`](starter/)

Готово и проверено тестами (`pytest -q Лекция_15/starter`, без модели):

| Файл | Что внутри |
| --- | --- |
| `spawn.py` | `spawn_subagent` по слайду 18 на протоколе каркаса; инструменты читателя (только чтение, только свои типы записей); оценка токенов; трасса-дерево `tree()` как на слайде 26 |
| `contracts/*.json` | схемы `problems_list`, `med_list`, `lab_summary` (слайд 19), `imaging_summary`, `critic_review` |
| `orchestrate.py` | задачи с полем `known` (слайд 16), четыре читателя параллельно с таймаутом и одним повтором (слайды 21–22), сборщик без выбора дат (слайд 23), критик с чистым окном и пределом в два круга (слайд 24), запись только у оркестратора |
| `fixtures/` | ответы-заглушки: четыре читателя, критик, а также плохие артефакты — без source, с инъекцией, с лишним полем |
| `tests/test_contract.py` | 13 тестов: три со слайда 20, фильтр схемы, права читателя, таймаут, partial, критик, граф целиком, пауза врача, стенд |
| `measure.py` | `python measure.py` — три строки таблицы слайда 28 на локальной модели → `bench.csv` и деревья трасс в `traces/` |
| `cases/P-0042.json` | один случай с ожидаемым содержанием пакета |

Что остаётся вам:

1. Довести `cases/` до 10 пакетов — данные других пациентов есть в `P-0042/data/`.
2. Написать `revise()` — правку пакета по замечаниям критика; сейчас это заглушка.
3. Уравнять бюджет: подобрать `budget_steps` в `measure.py`, чтобы токены одиночного агента во второй строке совпали с многоагентной.
4. Прогнать на локальной модели и сдать `bench.csv` и одно дерево трассы.

Токены считаются оценкой (около трёх символов на токен), а не счётчиком сервера модели. Для сравнения устройств этого хватает; если ваш сервер отдаёт `usage`, можно подставить точные числа.

Решение пишут в своей копии репозитория, в отдельной ветке; код каркаса можно менять и расширять.

## Что сдают

Сдают код, зелёные тесты, таблицу замера и трассу одного прогона в виде дерева.
