# Практикум 16 · A2A и надёжное исполнение

Лекция 16. A2A и надёжное исполнение. Задание — [слайд на сайте курса](https://edwfa.github.io/mas-lecture/lecture/16/slide-30.html).

Внешняя лаборатория для мини-harness лекций 13–15. Лаборатория — заглушка, A2A — настоящий формат.

## Что сделать

1. **Клиент.** Отправка задачи, GetTask, CancelTask; заголовок A2A-Version; карточка из репозитория.
2. **Состояние.** Запись случая в SQLite после каждого шага; продолжение после перезапуска.
3. **Запись.** chart_write с ключом и условным созданием; приём push с дублями.
4. **Тесты.** Убить посреди задачи; два уведомления; INPUT_REQUIRED через паузу врача.

## Файлы решения

- `lab_card.json` — карточка в репо
- `a2a_client.py` — send · get · cancel
- `store.py` — состояние случая
- `chart_write.py` — идемпотентная запись
- `test_restart.py` — убить и продолжить

## Что уже есть в каркасе P-0042

- [`data/timeline_P-0042.jsonl`](../P-0042/data/timeline_P-0042.jsonl) — результат BRCA в среду, уведомление приходит дважды

## Стартовый код — папка [`starter/`](starter/)

Готово и проверено тестами (`pytest -q Лекция_16/starter`, без сети и без модели):

| Файл | Что внутри |
| --- | --- |
| `lab_card.json`, `lab_pin.json` | карточка лаборатории (слайд 7) и то, что мы о ней закрепили: адрес, версия, навык; подмена адреса отклоняется |
| `a2a_client.py` | A2A 1.0, HTTP+JSON: `POST /message:send`, `GET /tasks/{id}`, `POST /tasks/{id}:cancel`; заголовок `A2A-Version: 1.0` в каждом запросе |
| `fake_lab.py` | лаборатория-заглушка: состояния, артефакт, INPUT_REQUIRED, push «хотя бы раз», журнал запросов |
| `store.py` | SQLite: запись случая после каждого шага, принятые уведомления, журнал записей, трасса; миграция v2 → v3 |
| `chart_write.py` | запись по слайду 19 (журнал + If-None-Exist) и компенсация по слайду 23 |
| `workflow.py` | граф случая NGS, `start_case` / `resume_case`, `on_push` по слайду 20, отмена и отсечка |
| `contracts/ngs_result.json`, `fixtures/` | схема артефакта (слайд 14), нормальный результат и результат с «назначьте алпелисиб» |
| `tests/test_restart.py` | 13 тестов: убить и продолжить (слайд 26), падение между отправкой и сохранением, между сервером и журналом, INPUT_REQUIRED через паузу врача, чужой токен, только поля схемы за границу, отмена конечной задачи, компенсация |

Сценарий тестов повторяет хронологию P-0042: задача `t-81c4`, перезапуск во вторник, «Укажите номер блока FFPE», ответ врача в пятницу, уведомление о готовности дважды.

Что остаётся вам:

1. Подключить граф к мини-harness: пакет к консилиуму берёт NGS из записи случая или пишет «результат ожидается».
2. Добавить в трассу случая связь с trace из лекции 13 (span по taskId, слайд 25) и сдать трассу с перезапуском и дублем.
3. По желанию — поднять настоящий A2A-сервер лаборатории из `a2a-sdk` и прогнать `HttpTransport` против него.

Формат push-уведомления и имя заголовка токена в заглушке упрощены; сверяйте с a2a-protocol.org для версии вашего сервера.

Решение пишут в своей копии репозитория, в отдельной ветке; код каркаса можно менять и расширять.
